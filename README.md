# 带宽账单最优的流量调度系统

面向多机房、按月第九十五百分位(95th percentile)峰值计费的短剧分发场景,
以**月带宽账单最低**为目标的流量调度仿真与决策系统。纯 Python + NumPy,
离线标杆用 SciPy 做小规模 MILP 对拍验证。

## 计费规则与统一建模

每 5 分钟一个采样点,每月 8640 个点;降序去掉最高的 5%(432 个点 = 36 小时),
剩余最大值即 **95 计费线**。这 432 个点是"白送"的免费高峰,调度的核心就是
把峰值流量精准堆进这些免费槽,其余槽压在计费线以下。

`billing.SiteConfig` 把四类商务条款统一建模:

| 条款 | 建模方式 |
|------|----------|
| 普通 95 峰值 | `unit_price × max(计费线, 0)` |
| 带保底 | 固定费 `commit_price × commit_mbps`,用不到也付;超保底部分按单价 |
| 阶梯价 | `tiers` 支持分段边际价(`marginal`)和整单价跳档(`whole`) |
| 包端口 | `port_fee` 固定月租,边际成本为 0,物理上限 `capacity_mbps` |

## 模块结构

```
bandwidth_scheduler/
├── billing.py      统一计费模型、95 线、免费槽、阶梯价、保底
├── simulation.py   三个月流量仿真(日周期/周效应/增长/爆款尖峰)、
│                   质量矩阵、故障事件、DNS 权重一阶惯性滞后模型
├── allocator.py    给定计费线的分配核心:全三元组全局贪心(LP 等价,
│                   固定 μ 下与运输 LP 浮点级一致)+ μ 二分满足平均质量
├── offline.py      离线最优标杆:凸松弛迭代(免费槽/计费线交替)+
│                   多起点 + 全局高峰削峰,真实账单函数择优
├── forecast.py     EWMA 星期几×日内槽形状预测,向量化、带冷启动兜底
├── online.py       在线滚动调度:免费额度节奏、计费线软帽、每日重排、
│                   故障立即重排、DNS 滞后开环补偿
├── policies.py     就近 / 平均分摊两个对照 + 统一仿真运行器;
│                   单槽运输 LP 承接(_realize_slot,约束矩阵缓存)
├── evaluation.py   账单、与最优差距、质量门槛、免费时段利用、尖峰日、
│                   MAPE/WMAPE 预测误差
└── report.py       自包含 HTML 报告(内联 SVG,无外部依赖)
```

## 核心算法

### 分配核心(allocator.py)

固定每站点每槽上限与线性成本后是一个 LP:需求等式 + 站点容量不等式 +
最差质量硬门槛(变量置零)+ 全局平均质量约束。引入质量约束对偶 μ 后,
每个 (地区,站点) 对的调整后成本为 `c[s] − μ·q[r,s]`,全部三元组按成本
升序贪心填充即得 LP 精确解。μ 二分搜索,顶点跳变处用凸组合插值使质量
恰好达标。

### 离线标杆(offline.py)

95 峰值直接写 MILP 有 S×8640 个二进制变量,通用求解器解不动。利用结构做
凸松弛:固定免费槽集合 → LP 求负载 → 重定计费线与免费槽 → 交替迭代。
多起点(全局高峰削峰 / 可行解 / 均匀 / 保底 / warm),每轮用真实账单
(含非凸阶梯)择优。小规模实例与 `scipy.optimize.milp` 精确解对拍
(`tests/test_offline_vs_milp.py`)。

### 在线调度(online.py)

- **免费额度节奏**:按月份进度线性释放 432 个免费点,月初宽松月末收紧,
  既不早用光也不留到月底浪费;
- **槽位分级**:免费槽放开到物理容量,普通槽压在 `计费线 × soft 系数`,
  透支时压到线下,保底量始终保留;
- **滚动重排**:每天在 3 天预测窗口上跑一次缩短视野离线优化(只优化未来,
  历史通过当前计费线/剩余额度注入,避免平方级开销);故障立即重排;
- **DNS 滞后补偿**:`w = x* + (1/k)(x* − x_prev)` 开环补偿一阶惯性。

## 运行

```bash
# 完整三个月(约 5~6 分钟)
python3 -m scripts.run_experiment

# 快速冒烟(2 个月 × 6 天,约半分钟)
python3 -m scripts.run_experiment --smoke --days 6

# 测试(13 个,含 LP/MILP 对拍、故障兜底)
python3 -m pytest tests/ -q
```

产出 `outputs/report.html`(账单对比、每机房排序采样曲线 + 当前计费线、
免费时段利用、尖峰日表现、预测误差)和 `outputs/metrics.json`。

## 质量约束的处理

最差质量是硬门槛。在线执行环节每个 5 分钟槽解一个**单槽运输 LP**
(`policies._realize_slot`,8 地区 × 12 机房 = 96 变量,HiGHS 亚毫秒级):
合格性作为变量上界为 0 的硬约束、物理容量为不等式、DNS 目标份额转为目标
系数,从数学上保证只要存在全合格可行解就绝不把用户调到远机房,同时在
合格站点内最贴合调度器下发的份额。故障叠加容量紧张导致合格容量物理不足
时,放开非合格站点并给高惩罚目标,把违约流量导向质量最高的站点、保证
不丢流量,并在 `viol_flow_ratio` 如实披露(三个月仿真正常工况为 0)。

## 预测模型(forecast.py)

按"星期几 × 日内 288 槽"维护 EWMA 绝对量级模板,首日直接用真实日均值
初始化 level(避免从 1 缓慢爬升),趋势修正用同口径的"近期日均 / 模板
全天均值"逐地区计算并限幅。标准 MAPE 评估:稳定期普通日约 19%、尖峰日
约 31%(爆款尖峰本质不可预测),每月首日冷启动约 42%。

## 关键设计取舍

- 分配核心的全局贪心相对精确运输 LP,固定 μ 下差距为浮点舍入量级;
  完整问题(含质量顶点跳变)差距 <0.5%,换取约两个数量级加速,使每日
  重排可行;在线实际承接改用单槽精确 LP 保证质量门槛零违约。
- 离线启发式是标杆而非数学最优;MILP 对拍显示小规模下次优差距 <5%。
- 在线策略在三个月仿真中稳定优于就近/平均分摊,与离线标杆的账单差距
  约 3%~7%(就近/平均分摊则超支 40%~86%),差距主要来自预测误差、
  DNS 滞后和故障,符合预期。全部策略质量硬门槛零违约、需求零丢弃。
